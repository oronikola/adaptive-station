# IP-003 — Milestone 2: Device API and Local-First Synchronization

**Date:** 2026-09-02  
**Status:** Planned  
**Depends on:** IP-002

## Objective

Replace the kiosk's direct remote-MySQL dependency with the Adaptive Station HTTPS API while preserving fast offline tapping and durable SQLite-first synchronization.

## Deliverables

- Authenticated station activation/session flow.
- Idempotent tap-event batch-upload API.
- Cursor-based master-data and station-configuration API.
- Device heartbeat and sync-health telemetry.
- Updated .NET 8 WPF kiosk with local SQLite migrations and API sync client.

## Work Plan

1. Add cloud migrations/models for `people`, `rfid_cards`, `tap_events`, `master_data_changes`, `device_sync_cursors`, and `device_heartbeats`.
2. Implement station activation: validate code, create/store protected credential locally, bind station and tenant, and write audit log.
3. Implement short-lived device sessions or signed access tokens derived from a station credential.
4. Implement `POST /api/v1/device/events/batch`; derive tenant/station from authentication and reject mismatched payload identities.
5. Enforce UUID idempotency: previously accepted event IDs return accepted without a second insert.
6. Implement master-data change recording for person/card/configuration upserts, deactivations, and deletions.
7. Implement `GET /api/v1/device/master-data?cursor=...`, `GET /api/v1/device/config`, and `POST /api/v1/device/heartbeat`.
8. Update the WPF app: remove remote MySQL lookup/write flow, add `AdaptiveStationApiClient`, retain keyboard-wedge input, duplicate protection, local IN/OUT logic, and scan-result UX.
9. Update local SQLite schema with identity, people/card cache, tap event sync fields, and cursor state.
10. Apply master changes transactionally; mark uploaded events synced only after API acknowledgement.
11. Add retry/backoff, bounded batches, detailed local errors, and admin-visible manual sync.

## Required Test Scenarios

- Tap while fully offline; restart kiosk; reconnect; verify one cloud event per local UUID.
- Submit identical upload batch repeatedly; verify no duplicate rows.
- Deactivate a card in portal; sync kiosk; verify offline rejection after cache update.
- Disable a station; verify the device cannot obtain a new session or upload new events.
- Simulate malformed batch item; verify accepted events and rejected events are reported separately.

## Verification / Exit Criteria

- A pilot kiosk runs without remote MySQL credentials.
- Valid offline taps are saved locally and synchronize after connectivity returns.
- Portal displays station last seen, pending count, and last successful sync.
- Sync correctness and tenant isolation are covered by automated API tests plus manual kiosk outage tests.

# IP-006 — Milestone 5: Pilot Hardening and Production Release

**Date:** 2026-09-02  
**Status:** Planned  
**Depends on:** IP-001 through IP-005

## Objective

Validate Adaptive Station under real operational conditions, complete the pilot migration safely, and release it for controlled production use.

## Deliverables

- Production deployment, monitoring, backup/restore, and support runbook.
- Security and resilience test evidence.
- Pilot-school training material and station activation guide.
- Parallel-run reconciliation and production acceptance sign-off.

## Work Plan

1. Prepare production infrastructure: HTTPS certificates, MySQL backups, queue workers, Redis/database queue, scheduled jobs, centralized logs, error alerts, and health monitoring.
2. Conduct security review: tenant-isolation tests, station-token rotation/revocation, authorization checks, secret redaction, password-first-run controls, and audit-log completeness.
3. Conduct resilience testing: extended offline operation, application restart while pending, intermittent network, API timeout, duplicate retries, cache deactivation, and disabled station behavior.
4. Test database restore and kiosk SQLite backup/export recovery procedures.
5. Provision the pilot tenant, import/migrate data, resolve exceptions, activate stations, and complete initial cache downloads.
6. Run Adaptive Station and the legacy reporting flow in parallel for an agreed validation period.
7. Reconcile attendance daily; investigate count or state discrepancies before final cutover.
8. Train platform support staff and school administrators on station activation, card management, reports, sync health, and incident escalation.
9. Execute staged cutover by station, monitor pending queues and errors, and retain rollback readiness until reconciliation closes.
10. Conduct post-launch review and prioritize defects or post-MVP enhancements.

## Release Gates

- No unresolved critical security or tenant-isolation defect.
- No confirmed loss of valid offline tap events in outage/recovery tests.
- Backup restore and local-kiosk recovery tests pass.
- Pilot roster/card/event imports reconcile within agreed tolerance; all exceptions have an owner.
- School administrators can complete essential day-one workflows without database access.
- Support runbook, monitoring ownership, and incident contacts are available.

## Verification / Exit Criteria

- Pilot-school acceptance is documented.
- All live stations report health and can synchronize reliably.
- Legacy export, if enabled, remains reconciled through the agreed transition period.
- The platform has a clear go-live, rollback, and support procedure.

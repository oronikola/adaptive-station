# IP-005 — Milestone 4: Existing School Management System Connectivity

**Date:** 2026-09-02  
**Status:** Planned  
**Depends on:** IP-001, IP-003, and IP-004

## Objective

Onboard the pilot school from its existing live tapping/SMS environment without making Adaptive Station or its kiosks dependent on legacy tables at runtime.

## Deliverables

- Tenant-scoped integration profile and queued connector driver for the pilot school.
- Legacy roster/card import and historical tapping-data migration.
- Optional one-way Adaptive Station-to-legacy attendance export.
- Import exceptions, reconciliation report, and transition-run visibility.

## Work Plan

1. Add migrations/models for `integration_profiles`, `integration_runs`, `import_batches`, and `import_exceptions`.
2. Implement encrypted integration configuration; allow secrets only to server-side queue workers.
3. Build the pilot connector, preferring a documented API; otherwise use a restricted database account.
4. Import `studinfo`, `teacher`, grade/section data, contact details required by the pilot, and RFID mappings into `people` and `rfid_cards`.
5. Import `taphistory` and selected kiosk-local SQLite attendance into `tap_events`, preserving source time/state and source identifiers.
6. Use `(tenant_id, source_system, source_record_id)` to make re-runs safe. Flag ambiguous fallback matches rather than guessing.
7. Provide portal/import-job status with counts for scanned, imported, skipped-known, rejected, and manual-review records.
8. Implement and test optional legacy attendance export, matching the pilot's expected `taphistory` format and mapping.
9. Schedule queue jobs, logging, retry policy, and reconciliation reports.
10. Document field ownership and cutover criteria; do not enable uncontrolled bidirectional editing.

## Security Constraints

- Kiosk machines never receive legacy MySQL credentials.
- Use read-only access for roster imports whenever possible.
- Store legacy credentials encrypted and redact them from logs/errors.
- Restrict legacy export accounts to required target tables/operations.

## Verification / Exit Criteria

- Pilot roster and active cards import correctly and reach a kiosk cache.
- Re-running an import does not duplicate people, cards, or tap events.
- Exceptions are visible and resolvable instead of silently ignored.
- Legacy versus Adaptive Station attendance counts reconcile for the agreed sample period.
- Optional export produces accepted legacy-format records without affecting kiosk tap availability.

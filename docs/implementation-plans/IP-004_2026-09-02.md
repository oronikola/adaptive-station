# IP-004 — Milestone 3: School Administration and Reporting

**Date:** 2026-09-02  
**Status:** Planned  
**Depends on:** IP-002 and IP-003

## Objective

Enable a school administrator to operate Adaptive Station through the portal without database access or developer intervention.

## Deliverables

- Portal CRUD for people, RFID cards, stations, and school users.
- Attendance search, daily summaries, and CSV export.
- Station-health and synchronization-status pages.
- Kiosk display/operational configuration delivered through the device API.

## Work Plan

1. Build people management with student/staff type, names, grade/section, active status, photo reference, and optional metadata.
2. Build RFID-card assignment, replacement, deactivation, UID normalization, and duplicate prevention per tenant.
3. Emit `master_data_changes` for all kiosk-relevant changes.
4. Build station details: status, activation, configuration, credential rotation, last seen, last scan, queue count, and recent sync errors.
5. Build attendance reporting filtered by school date, person, card UID, station, and IN/OUT state.
6. Add daily summary and CSV export, respecting the tenant timezone.
7. Build tenant-user management for admins/operators and audit all management actions.
8. Add portal validation, empty/error states, pagination, authorization checks, and accessibility review.
9. Test the full workflow: create person, assign card, sync kiosk, tap, locate event, and export report.

## Data Rules

- Daily reporting uses `attendance_date_local`; event instants remain stored in UTC.
- Deactivated cards/persons remain visible historically but cannot be used by updated kiosk caches.
- Do not let tenant administrators modify another tenant's station or attendance data through IDs, URLs, exports, or search filters.

## Verification / Exit Criteria

- School admin can provision a person/card and have it available on a synchronized kiosk.
- School admin can locate and export the same day's attendance without SQL access.
- Health page identifies an offline station and its last known pending count.
- All mutations create audit-log records.
